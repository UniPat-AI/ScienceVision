# ev2 Pilot — Three-Way Baseline Comparison (Harbor)

**Benchmark:** ScienceVision 3D-grounded QA, ev2 pilot set — **15 tasks** across
3 domains (biology ×4, chemistry ×8, medical ×3).
**Agent model (all baselines):** `claude-opus-4-8`.
**Harness:** Harbor, `--env docker`, verifier
`harbor_adapters.sci3d.verifier:Sci3dVerifier`.
**Run date:** 2026-07-30 — a single clean run of all 15 tasks × 3 baselines
(45 trials). No rerun was needed this time.

> **What the three baselines isolate.** All three drive the *same* `claude` CLI
> agent on the *same* 15 questions. The only thing that changes is **what the
> agent can see and do with the 3D asset** — i.e. the input modality and the
> tool surface. This is a controlled ablation of "does giving the agent real 3D
> access (raw file / MCP tools) beat giving it only pre-rendered pictures?"

## 2. The three baselines — input / output / rubric / trajectory

### 2.1 Shared task format

Every task hands the agent an **instruction** plus a fenced `sci3d` block
pointing at the asset. For example, the instruction text reads:

> Locate the chiral center(s) in the displayed molecule and assign the R/S
> configuration from the 3D geometry. — Asset: `/data/3672_ibuprofen.mol`

followed by a fenced `sci3d` block carrying the asset pointer as JSON:
`{"asset_path": "/data/3672_ibuprofen.mol"}`.

**Output.** The agent answers in free text (its final assistant message). The
verifier reads `sci3d_answer.json` if the agent wrote one, else falls back to
the last message in `trajectory.json` — both are scored identically.

### 2.2 Shared eval rubric

Each trial's `reward ∈ [0,1]` is a weighted sum:

```
reward = 0.7 · content + 0.3 · process        (clamped to [0,1])

content  = mean of non-process scorer keys  → here just llm_judge
           (expert_reference_match: an LLM judge compares the answer to the
            task's expert-reference ground truth under a domain rubric)

process  = mean of:  process_judge            (LLM judge of trajectory quality)
                     process_opened_scene      {0,1}  used an open-scene tool
                     process_rendered          {0,1}  used a render tool
                     process_tool_policy       {0,1}  no forbidden tools, stayed in allow-list
                     process_finished          {0,1}  used a finish tool
                     (1 − process_metadata_only) {0,1} did NOT shortcut via metadata only
```

Each `task.toml` carries `allowed_tools` (e.g. `sv3d_open_scene`, `sv3d_render`,
`sv3d_reslice`), `forbidden_tools` (e.g. `cip_assignment_api`,
`metadata_lookup_answer`), an `answer_schema`, a `scorer`
(`primary = expert_reference_match`), and an expert-reference `ground_truth`.

> **Why a wrong answer still floors at ~0.100:** with `content = 0` and
> `process_judge = 0`, an agent that merely stayed in-policy still gets
> `process_tool_policy = 1` and `(1 − metadata_only) = 1`, so
> `process = 2/6 = 0.333` → `reward = 0.3 · 0.333 = 0.100`. This 0.100 is the
> structural floor — and, as §5 explains, exactly the value a judge outage
> masquerades as.

### 2.3 Per-baseline input, tool surface, and trajectory behavior

| | `cc` (plain) | `cc2d` (2D multiview) | `ccmcp` (MCP 3D) |
|---|---|---|---|
| **Docker image** | `sci3d-claude-code` | `sci3d-claude-code-2d` | `sci3d-claude-code-mcp` |
| **What's in `/data`** | raw 3D file (`.mol/.cif/.xyz/.nii.gz`) | **`views/*.png` only — no raw asset** | raw 3D file |
| **3D libraries / MCP** | none | none | sciencevision MCP (`sv_inspect_*`, `sv3d_*`, `sv_render_*`) |
| **Typical trajectory** | Bash-heavy: writes ad-hoc shell/py to poke the raw file | minimal: `Read`s the PNGs, reasons from pixels | rich: `sv_inspect_molecule` / `sv_inspect_nifti` / `sv3d_open_scene` / `sv_render_nifti_mip` … |
| **Observed tools** | Bash-heavy (ad-hoc shell/py), some Read | Read (the PNGs), light Bash | Bash + Read **plus** distinct `mcp__sciencevision__*` tools (verified — see below) |

**`cc` — plain.** Sees the raw file but has no 3D libraries. It improvises with
Bash (many `Bash` calls) — e.g. hand-parsing `.mol` coordinates and computing a
chirality triple-product in a shell one-liner, or falling back to raw
`gzip`+`struct` NIfTI-header parsing when `pip install nibabel` times out.
Capable on parseable text formats (chemistry `.mol/.xyz`), weaker where it
needs real rendering/segmentation — this run's `sv-medi-mri-arbitrary-plane-02`
even hit an `AgentTimeoutError` at 1800s for `cc` while `cc2d`/`ccmcp` answered
it fine (see §6).

**`cc2d` — pure vision.** The security invariant is that the raw asset is
**never** staged; only offline-rendered PNG views are. This is a genuine
pure-vision baseline. **Critical limitation:** molecular/point-cloud renders are
deferred (`views_missing`), so for most chemistry/biology tasks the `views/`
dir is **empty** and the agent sees *nothing* — it can only answer generically
("paste the molecule and I'll assign…"). It does have real views for medical
NIfTI (slices render), which is why it is competitive — and this run actually
*wins* the medical domain (§3.1).

**`ccmcp`— MCP 3D.** Sees the raw file *and* has the sciencevision MCP tool
loop. It actually inspects and renders the 3D structure, e.g.
`sv_inspect_molecule`, `sv_inspect_nifti`, `sv_render_nifti_mip`,
`sv_render_nifti_slice`, `sv3d_open_scene`, `sv3d_render_canonical_views`.
Highest `llm_judge` (content) of the three, but this run its `process_judge`
mean (0.639) fell just below `cc`'s (0.681) — see §1 and §6.

### 2.4 Two worked examples (same task, three baselines)

**`sv-chem-chirality-07`** — ibuprofen `.mol`; expert-ref GT: chiral center
`C2`, config `R`.

|---|--:|--:|---|
| `cc` | 0.809 | 0.95 | 3-step trajectory: one `Read` of the raw `.mol` file, then computed CIP priorities and the R/S handedness from the coordinates by hand (triple product), concluding **"atom 7 (labelled C7 in the file), configuration R"** — same conclusion as before, but this run the judge scored it `0.95`. |
| `cc2d` | 0.115 | 0.00 | 3-step trajectory: ran `Bash ls /app`, found the working directory **empty** (no view was rendered for this molecule), and answered with a generic "there's no molecule available to analyze… please provide a structure file" — floor. |
| `ccmcp` | 0.634 | 0.85 | 6-step trajectory: two failed `sv_inspect_molecule` calls (wrong/missing args), then a successful one returning atom/bond counts, then a `Read` of the raw molfile to get coordinates, then the same CIP/triple-product method as `cc`, concluding the **same "atom 7 (C7), R"** answer — content scored `0.85`. |

> before (`cc`/`ccmcp` both call the stereocenter "C7" from the file's atom

> correct in both. This run the judge scored `cc`'s answer `0.95` and `ccmcp`'s
> `0.85` — a smaller and reversed gap vs the old report, underscoring the
> judge-variance caveat in §6.

**`sv-medi-anatomical-region-01`** — hippocampus NIfTI; GT: structure
`hippocampus`, plane `oblique-coronal`, boundary slices `[29,32]`.

| baseline | reward | content | trajectory |
|---|--:|--:|---|

## 5. Scoring integrity — the judge-503 story, and why this run needed no rerun

Earlier runs (2026-07-23) hit a **judge 503 outage**: every task tied at
`reward = 0.100`, which looks like "all baselines are equally bad" but was
actually a scoring failure, not a result:

- The verifier's LLM judge defaults to the **dated** id
  `claude-haiku-4-5-20251001`, which the ALB gateway does not serve
  (`HTTP 503 … channel pricing restriction`). When the judge 503s, both
  `llm_judge` and `process_judge` degrade to `0.0` and reward collapses to the
  0.100 process floor (§2.2).
- **The fix, applied at run time in THIS fresh run:** the harbor invocation
  pinned the **undated** `claude-haiku-4-5` via
  `--verifier-kwarg judge_model=claude-haiku-4-5` (HTTP 200), and the offline
  rescore path (`scripts/harbor/rescore_rerun.py`) remains the authoritative
  scoring step. Because the judge was healthy throughout, all **45 cells
  scored cleanly on the first pass** — tiers per baseline are **0 rerun / 15
  rescored / 0 degraded**, with no errored-trial rerun tier needed this time
  (unlike the 2026-07-27 report, which had to re-run 6 trials).
- The two errored/floored outcomes in this run's table (§3.2, §6.3) are
  **honest results, not harness failures**: `sv-chem-optimization-vector-06`
  refused in all three baselines, and `cc`'s `sv-medi-mri-arbitrary-plane-02`
  hit an `AgentTimeoutError` at 1800s. Neither was rerun to "fix" the number.

> **Gotcha (still true):** `--ae SCI3D_JUDGE_MODEL=…` injects the env
> into the **agent** container only. The verifier runs in a *separate*
> container (`environment_mode = separate`), so it never sees an `--ae`
> override and would still 503 on the dated judge id. The judge model must be
> pinned via `--verifier-kwarg judge_model=…` at run time, and the offline
> rescore (`scripts/harbor/rescore_rerun.py`) is kept as the authoritative
> path regardless.

## 6. Findings & caveats

1. **Ground truth is provisional.** Every `task.toml` GT is marked
   `status = "needs_expert_annotation"` / "Illustrative … requires expert
   sign-off". Absolute scores are **not** publishable accuracy; treat the
   comparison as *relative* between baselines under one judge.
2. **Judge variance.** The near-identical stereocenter-labelling logic on
   `sv-chem-chirality-07` scored `0.95` (`cc`) vs `0.85` (`ccmcp`) this run —
   smaller than the earlier 0.0-vs-0.60 gap, but still a reminder that
   single-judge, single-sample scoring has real noise; multi-sample /
   multi-judge would tighten it.
3. **`sv-chem-optimization-vector-06` = ~0.100 across all three baselines is a
   real agent refusal, not a flake.** The prompt (ligand substitution vectors
   into an acetylcholinesterase gorge subpocket) trips a false-positive Usage
   Policy refusal (`model_refusal_no_fallback` → "unable to respond … violates
   our Usage Policy"). The agent emits no answer → floor. Worth rewording the
   task or flagging the refusal.
4. **`cc2d` is blind on molecules.** Its low chemistry/biology scores are
   largely an artifact of `views_missing` (molecular renders deferred), not of
   vision being intrinsically weak. A fair pure-vision molecular baseline needs
   the molecular renderer enabled — and this run's medical-domain win for
   `cc2d` (§3.1) shows the modality is competitive once real views exist.
5. **`process_*` closed-loop signals do NOT hand `ccmcp` the process lead this
   run.** In principle only `ccmcp` can call `sv3d_open_scene`/`sv3d_render`,
   so `process_opened_scene`/`process_rendered` structurally favor it. But
   the mean `process_judge` this run is actually higher for plain `cc`
   (0.681) than for `ccmcp` (0.639) — see §1. The 30% process weight did not
   translate into a process win for the tool-equipped baseline this time;
   `ccmcp`'s advantage is concentrated in content, not process.
6. **`sv-medi-mri-arbitrary-plane-02` timed out for `cc` this run** — an
   `AgentTimeoutError` at 1800s, with `cc2d` and `ccmcp` both answering
   normally on the same task. This is an honest outcome of this fresh run
   (not rerun away) and pulls `cc`'s medical-domain mean down (§3.1).
