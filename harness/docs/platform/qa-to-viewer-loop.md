# QA-Gen → viewer reload loop

> How a freshly generated QA-Gen batch becomes a card in the viewer.
> Companion to [`../qa-gen/pipeline-overview.md`](../qa-gen/pipeline-overview.md).

---

## 1. Data flow

```
   QA-Gen/tasks/<name>/                      one directory per batch
   ├── generation_stats.json                 ← load-bearing metadata
   ├── <Name>_final_tasks.jsonl              ← accepted tasks
   ├── REVIEW.md            (optional)
   └── GENERATION_STATS.md  (optional)
                       │
                       ▼
           tools/build_qagen_index.py        scans QA-Gen/tasks/*/generation_stats.json
                       │
                       ▼
            viewer/qagen_index.json          schema_version 1.0
                       │
                       ▼
       viewer/shared/sections/qagen.js       fetches index, renders cards
                       │
                       ▼
        cards rendered in viewer pages       qagen.html / index.html (Plan 3)
```

The loop is **fully deterministic**: `build_qagen_index.py` re-walks the
tasks directory and rewrites the JSON every run. The viewer fetches the
JSON at page load — no build step, no cache invalidation needed beyond
the page reload.

---

## 2. `qagen_index.json` schema (v1.0)

```json
{
  "schema_version": "1.0",
  "generated_at": "2026-06-05T07:06:02+00:00",
  "sets": [ { ...set entry... }, ... ]
}
```

### Top-level fields

| Field | Type | Notes |
|---|---|---|
| `schema_version` | string | currently `"1.0"`. Bump when fields are renamed or removed. |
| `generated_at` | ISO-8601 timestamp (UTC) | when `build_qagen_index.py` ran. |
| `sets` | array | one entry per batch directory under `QA-Gen/tasks/`. Sorted lexicographically by directory name. |

### Per-set entry

| Field | Type | Source | Notes |
|---|---|---|---|
| `name` | string | directory name | e.g. `MedicalKAxisPilot`. |
| `dir` | string | repo-relative path | e.g. `QA-Gen/tasks/MedicalKAxisPilot`. |
| `kept_total` | int | `stats.task_counts.kept_total` | drives the "N kept" badge. |
| `generated_total` | int | `stats.task_counts.generated_total` | how many candidates were built. |
| `kept_ratio` | float | `stats.task_counts.kept_ratio` | drives the "accept X%" line. |
| `tokens_total` | int | `stats.token_usage.total_tokens_total` | 0 for deterministic v1 batches. |
| `cost_usd_total` | float | `stats.cost.cost_usd_total` | 0.0 for deterministic v1 batches. |
| `has_review_md` | bool | `(set_dir / "REVIEW.md").exists()` | drives the REVIEW link on the card. |
| `has_coverage_md` | bool | `(set_dir / "GENERATION_STATS.md").exists()` | drives the GENERATION_STATS link. |
| `tasks_jsonl` | string | first match of `*final_tasks.jsonl` | repo-relative path; empty string if no JSONL found. |

A batch directory **without** `generation_stats.json` is silently
skipped (logged to stderr). This is intentional — half-baked batches
do not crash the viewer; they simply don't appear.

---

## 3. `generation_stats.json` contract

This is what each batch **must** ship for the viewer to pick it up.

```json
{
  "schema_version": "1.0",
  "set_name": "MedicalKAxisPilot",
  "set_version": "v3",
  "task_counts": {
    "generated_total": 4,
    "kept_total": 4,
    "filtered_total": 0,
    "kept_ratio": 1.0
  },
  "token_usage": {
    "total_tokens_total": 0
  },
  "cost": {
    "cost_usd_total": 0.0
  },
  "by_k_class": { "K2": 1, "K3": 1, "K5": 2 },
  "ground_truth_status_distribution": { "auto_seed": 4 }
}
```

Required keys for the builder: `task_counts.{kept_total, generated_total,
kept_ratio}`, `token_usage.total_tokens_total`, `cost.cost_usd_total`.
Anything else is informational. A batch generated by the deterministic
v1 path may leave `token_usage` and `cost` at zero.

Worked example: `QA-Gen/tasks/MedicalKAxisPilot/generation_stats.json`.

## 4. Registering a new batch — the loop

For a batch generator (whether `build_records.py` or the upstream
`sciencevision_taskgen.runner`) the contract is:

1. Write `QA-Gen/tasks/<name>/<Name>_final_tasks.jsonl` (records per
   the schema in [`../qa-gen/pipeline-overview.md`](../qa-gen/pipeline-overview.md) §5).
2. Write `QA-Gen/tasks/<name>/generation_stats.json` per §3 above.
3. Optionally write `REVIEW.md` and `GENERATION_STATS.md` next to them
   — these only affect the two metadata links on the card.
4. Run the index builder:

   ```bash
   python3 tools/build_qagen_index.py
   ```

   Output: `viewer/qagen_index.json` is rewritten in place. Stderr
   reports skipped directories.

5. Reload the viewer (`viewer/qagen.html`). The new card appears.

Steps 1–3 are stable; step 4 is what closes the loop. Steps 1–2 always
ship in the batch directory itself — they're never side-channel state
the builder script needs to know about.

---

## 5. Viewer-side rendering contract

`viewer/shared/sections/qagen.js` fetches `/viewer/qagen_index.json`
and renders one `<article class="qagen-card">` per entry into the
element with id `qagen-grid`.

Each card composes:

- title: `set.name`
- counts: `{kept_total} kept · accept {kept_ratio × 100}%`
- "open task viewer" link: `/viewer/sciencevision_tasks.html?set=<name>`
- conditional links: `REVIEW.md` and `GENERATION_STATS.md` if their
  flags are true (path resolves to `/QA-Gen/tasks/<name>/{REVIEW,GENERATION_STATS}.md`)

The tab badge total is `sum(s.kept_total for s in sets)`. On fetch
failure the section shows a `pane-error` block with the rebuild hint:

```
Failed to load /viewer/qagen_index.json (...). 
Rebuild: python3 tools/build_qagen_index.py
```

Mount point — `<section id="qagen-grid">` — must exist in any page
that wants the renderer. The current `viewer/qagen.html` (created by
Plan 3) does **not** yet include that element; it ships as a static
task-family overview and is the place to wire `sections/qagen.js`
in when live data is needed.

## 7. Common pitfalls

- **Forgot to write `generation_stats.json`** — the batch silently
  disappears from the index. The stderr warning is the only signal:
  `WARN: skipping <name>: no generation_stats.json`.
- **JSON malformed** — same outcome, same warning shape:
  `WARN: malformed <path>: <error>`. No partial set is emitted.
- **Multiple `*final_tasks.jsonl` files in one batch dir** — the
  builder picks the lexicographically last one. If a batch ships both
  `*_seed_tasks.jsonl` and `*_final_tasks.jsonl`, only the latter
  matches the glob `*final_tasks.jsonl`, so this is usually safe;
  versioned names like `*_final_tasks_v2.jsonl` will win over
  `*_final_tasks.jsonl`. Keep one canonical name per batch.
- **`tasks_jsonl: ""`** in an entry — the batch has
  `generation_stats.json` but no JSONL matching the glob. Card still
  renders; the open-task-viewer link will produce an empty view.
- **`schema_version` drift** — the field exists for a reason. Any
  field rename or removal must bump the version, and `qagen.js` must
  be taught to read both for the migration window.
