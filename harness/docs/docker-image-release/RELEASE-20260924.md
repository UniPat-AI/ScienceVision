## Consumer-visible behavior changes

1. **View sets changed.** Any comparison against results produced with the old
   orbit plans is invalid for the mesh/CAD/molecule arms at n ∈ {1,3,6,12}. The
   new sets are the delivered `views-aligned/` scheme, so cc2d and ccmcp now
   sample identical cameras.
2. **`seed_pose` no longer shifts** frozen-protocol counts (it only affects the
   legacy orbit fallback for n ∉ {1,3,6,12}).
3. **Rendered pixels changed** (near plane, molecule frame, HETATM retention).
   Render cache entries from older builds are not reused (version keys); trees
   generated before this round should be regenerated rather than patched.
4. **Tool surface changed**: the two render tools advertise `angle_frame` (and
   `view` on the molecule tool) → the worker's schema hash changes with this
   image; a route-health receipt from the 0923 worker is not comparable.
5. **STEP tasks need the OCP kernel on the tree-generation host** (H20), not in
   the worker; without it they fail closed with `ocp_unavailable` and appear in
   the exclusion receipt.
6. **cc2d exclusions are receipts now**: a `*-2d` tree may be short of the
   eligible id set exactly by its `cc2d_exclusions.jsonl`; publish it with the
   tree audit so denominators are explicit.

## Known limits (deferred)

- **The worker image ships no GL stack.** Its pip list has no
  `pyrender`/PyOpenGL/EGL libraries (pre-existing; the 20260923 worker is the
  same), so its mesh/session render tools (`sv_render_mesh_thumbnail`,
  `sv3d_render*`) answer `dependency missing: pyrender`. The near-plane fix
  therefore lands where pyrender actually runs: the **host-side cc2d
  generation** (the 11 blank CAD views). Molecular renders do work in the
  worker (matplotlib, no GL) and receive this round's fixes. Giving the worker a
  GL stack is a packaging-contract decision (GPU passthrough vs software EGL)
  and is not part of this round.
- The HETATM fix keeps ligands in the picture; identifying a *named* atom inside
  a CPK cloud remains a question-design matter, not addressed here.
- `_load_structure` now returns a 3-tuple; the two out-of-repo aligned-view
  scripts under `SV-data/qc-rework/` still unpack 2 (one-line fix when rerun).
- Re-running the generator into the same `--out` can leave a stale
  `cc2d_exclusions.jsonl`; use fresh output directories (the harness convention).
- The snapshot renderer's near-plane fix is not pinned by its own test (the file
  is exercised only under real GL).
